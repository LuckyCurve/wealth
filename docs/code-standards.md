# Code standards

评审时逐条对照。每条为什么、曾经怎么坏，见 [LESSONS.md](../LESSONS.md) 的对应小节。

**形态类规则不在这里**：判据能从页面或文件自身求值的，一律写成测试（见文末表）。
在这里加一行之前先问：它能不能被测试守住？能就写测试。

## 判断类（测试守不住的）

| 规则 | 评审看什么 |
| --- | --- |
| 一个 commit 只做一件事。 | 顺手修的东西单独提交；无关重构不进功能提交。 |
| 兄弟一起改。 | 同类结构、同类入口、同一判定函数的所有调用点都查一遍：改了还是确认不用改，写进提交正文。 |
| 全路径。 | 从用户输入到落盘/渲染，把中间调用、状态变化和副作用走一遍；一个函数对不代表整个操作对。 |
| 单一来源。 | 同一逻辑/样式/结构出现 ≥2 次必须收敛。已有断言只钉住登记过的几处——**新入口自己判断**。 |
| 先验形状再写。 | 外部数据先校验再进 `state`；缺失、空串、非法值、数字 0 是四件事，不合并。 |
| 失败即未知。 | 读不到、解析失败不得当成「空」「没有」或「不存在」；保留上一次的好值，覆盖前先备份。 |
| 先红后绿。 | 新测试必须先失败，失败原因与预期一致；先改实现再补测试不算。 |
| 反验证。 | 修 bug 时把实现回退或改坏，确认新测试真的变红；不会红的测试等于没写。 |
| 测在哪一层。 | 计算样式、像素、可访问名、真实点击只有浏览器能验；其余下沉 `logic.js`。判据从页面自身求值，不写死元素清单。 |
| 判据的覆盖范围。 | 巡检类遍历页面求值，新增同类结构自动纳入；`fnSource` 点对点断言只钉住当前几处。当成全覆盖就会留洞。 |
| 文档不缓存可变数字。 | 注释/文档里出现耗时、字节数、用例条数 → 问一句「谁负责改它」。没人负责就是缓存：删掉，只留「拐点在哪、为什么这么选」。 |

## 已由测试守住（改测试，不改这里）

| 规则 | 守卫 |
| --- | --- |
| 可访问名、对比度 AA、原生控件外观、数字列右对齐、同类元素样式一致、弹窗有可见标题 | `e2e/consistency.spec.js` 六个 describe，判据从页面求值 |
| 存档/导入字段一律 `esc`，含 `id` 与 `data-*` | `ui-wiring`「图表 tooltip 转义用户输入」+ `e2e/app` 的 id/日期两条 |
| 迁移只有一个入口 `migrateState()` | `ui-wiring`「导入/导出（纯原始格式 + 迁移兜底共用一套）」 |
| 改名 ≠ 删除（迁移引用，不是清空） | `logic`「标签改名（引用迁移，不是删除重建）」+ `ui-wiring` + `e2e/app` 同名 describe |
| 不篡改历史（快照不随补） | `e2e/app`「资产侧数据校验（快照按当时数据保留，不随补）」 |
| 行级可点元素键盘可达、拖拽有键盘替代 | `ui-wiring`「行级可点元素必须键盘可达」+ `e2e/app`「指针与键盘两条路都要给」 |
| 读屏器要念的话写进可访问名 | `ui-wiring`「便条的播报优先级」+ `e2e/app` 的 aria-sort 一条；**新 `aria-*` 仍要人工判断** |
| E2E 不用 `waitForTimeout` | `test/e2e-hygiene.test.js` |
| E2E 不放行外网（不出现 `route.continue` / `unroute`） | `test/e2e-hygiene.test.js` 第二条 |

## 新增规则时

能写成检查的，别写进文档：先问「这条违规能不能让它变红」——能，就加断言（`node --test` 或某个 spec 的一条），文档里只留一行指针。只有**判断类**（跨文件一致性、像不像周围代码、取舍）才进上表。

规则与检查之间的缝不会自己合上：本仓曾有「E2E 不访问外网」这条规则，同时有一支 spec 放行 jsdelivr 连着外网跑了几周，而 CI 全绿。发现的路径不是更仔细地读，而是问「这条规则现在由什么把守」。
